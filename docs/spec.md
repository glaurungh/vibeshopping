# VibeShopping — Спецификация приложения

## 1. Vision

**VibeShopping** — это web-приложение для управления списками покупок.
Пользователи могут создавать списки, добавлять товары, отмечать купленные,
а также делиться списками с другими пользователями для совместного планирования
покупок.

**Целевая аудитория:** семьи, пары, соседи — любые люди, которые совместно
покупают продукты и товары.

## 3. Функциональные требования

### 3.1. Аутентификация

| ID    | Требование                                                                 | Ссылки на US |
|-------|----------------------------------------------------------------------------|--------------|
| FR-01 | Система поддерживает регистрацию по email и паролю                        | US-01        |
| FR-02 | Пароль хранится в БД в хешированном виде (bcrypt)                         | US-01        |
| FR-03 | При успешной аутентификации выдаётся JWT access-токен (срок: 1 час)      | US-02        |
| FR-04 | При успешной аутентификации выдаётся JWT refresh-токен (срок: 7 дней)     | US-02        |
| FR-05 | Refresh-токен позволяет получить новый access-токен без повторного логина  | US-02        |
| FR-06 | Email должен быть уникальным                                              | US-01        |
| FR-07 | Минимальная длина пароля — 8 символов                                     | US-01        |

### 3.2. Списки покупок

| ID    | Требование                                                                            | Ссылки на US |
|-------|----------------------------------------------------------------------------------------|--------------|
| FR-10 | Пользователь может создать список с названием                                         | US-10        |
| FR-11 | При создании списка пользователь автоматически становится его владельцем              | US-10        |
| FR-12 | Пользователь видит только списки, в которых он является владельцем или участником      | US-11        |
| FR-13 | Только владелец может переименовать или удалить список                                | US-12, US-13 |
| FR-14 | При удалении списка удаляются все его элементы и записи участников                      | US-13        |

### 3.3. Элементы списка

| ID    | Требование                                                                                    | Ссылки на US |
|-------|------------------------------------------------------------------------------------------------|--------------|
| FR-20 | Элемент списка содержит: название, количество (опционально), флаг «куплено»                   | US-20        |
| FR-21 | Владелец и участники списка могут добавлять элементы                                         | US-20, US-32 |
| FR-22 | Владелец и участники списка могут редактировать элементы                                      | US-22, US-32 |
| FR-23 | Владелец и участники списка могут отмечать элементы как купленные / не купленные               | US-23, US-24, US-33 |
| FR-24 | Владелец и участники списка могут удалять элементы                                           | US-25, US-32 |
| FR-25 | Некупленные элементы отображаются выше купленных (по умолчанию)                               | US-21        |

### 3.4. Совместные списки

| ID    | Требование                                                                                           | Ссылки на US |
|-------|-------------------------------------------------------------------------------------------------------|--------------|
| FR-30 | Только владелец списка может приглашать участников                                                   | US-30        |
| FR-31 | Приглашение осуществляется по email существующего пользователя                                         | US-30        |
| FR-32 | Один пользователь не может быть добавлен в список дважды                                              | US-30        |
| FR-33 | Только владелец может удалять участников                                                              | US-34        |
| FR-34 | Владелец не может удалить себя из списка (нужно передать владение или удалить список)                 | US-34        |
| FR-35 | При передаче владения текущий владелец становится обычным участником                                  | US-35        |
| FR-36 | Участник может покинуть список; если это последний участник (не владелец), список остаётся            | US-36        |

## 4. Нефункциональные требования

| ID    | Требование                                                                                         |
|-------|------------------------------------------------------------------------------------------------------|
| NFR-01 | Backend API должен отвечать менее чем за 200 мс для 95% запросов при нормальной нагрузке            |
| NFR-02 | Все API endpoints должны возвращать данные в формате JSON                                            |
| NFR-03 | API должен быть полностью задокументирован через OpenAPI (FastAPI auto-docs)                         |
| NFR-04 | Код должен покрываться тестами минимум на 80%                                                       |
| NFR-05 | Приложение должно быть доступно с мобильных устройств (адаптивный frontend / PWA)                    |
| NFR-06 | Пароли и токены не должны логироваться                                                              |
| NFR-07 | Миграции БД должны быть обратимыми (downgrade)                                                      |
| NFR-08 | Код должен соответствовать PEP 8 (с проверкой через ruff)                                           |

## 5. Выход за рамки текущей версии (v1)

Следующие возможности **не** входят в текущую версию, но могут быть добавлены позже:

- Категории товаров
- Единицы измерения (кг, литры, штуки)
- История покупок / аналитика
- Push-уведомления
- Экспорт/импорт списков
- Поиск товаров
- Автодополнение названий товаров
- Удаление аккаунта
- Сброс пароля через email
- Drag-and-drop сортировка

## 6. Глоссарий

| Термин      | Определение                                            |
|-------------|--------------------------------------------------------|
| Владелец    | Пользователь, создавший список. Имеет полные права.   |
| Участник    | Пользователь, приглашённый в список. Может управлять товарами, но не удалять список. |
| Элемент     | Запись в списке покупок: название, количество, флаг «куплено». |
| Refresh-токен | JWT-токен для получения нового access-токена без повторного входа. |
